# AP® Econ diagnostic — итерация 1

Диагностический тест по AP® Microeconomics, Unit 1. Вертикальный срез:
ученик открывает ссылку, отвечает на 15 вопросов и получает разбор.

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
```

Тест: `/practice-test/ap-microeconomics/unit-1`

```bash
npm run typecheck   # tsc --noEmit
npm run test        # подсчёт результатов и выбор почтового провайдера
npm run build
```

## Перед показом ученикам

1. **Почта преподавателя** — `src/config/cta.ts`, сейчас там
   `REPLACE_ME@example.com`.
2. **Фотография** — уже на месте: `public/olga.jpg`, кадрирована по голове и
   плечам под круглый аватар (512×512, 46 КБ). Если файл когда-нибудь
   пропадёт, компонент сам покажет монограмму «OS» — битой картинки не будет
   ни при каком раскладе.
3. **Отправка писем** — скопировать `.env.example` в `.env.local` и заполнить
   один из двух блоков:
   - **SMTP её ящика** (`SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`) — бесплатно,
     домен не нужен, письма уходят с её реального адреса. Для Gmail нужен
     «пароль приложения», обычный пароль не подойдёт. Это путь на время
     разработки.
   - **Resend** (`RESEND_API_KEY`, `EMAIL_FROM`) — когда появится свой домен:
     Resend без подтверждённого домена отправлять не даёт.

   Если заполнены оба, приоритет у SMTP. Если не заполнен ни один, формы
   работают, но письмо не уходит: пользователю показывается запасная ссылка
   mailto, а письмо печатается в консоль сервера. Молча терять заявки нельзя.

## Что входит в эту итерацию

- Роут `/practice-test/ap-microeconomics/unit-1` с тремя состояниями на одном
  URL: `idle` (лендинг и правила) → `running` (движок) → `done` (результаты).
  У движка нет своего URL: состояние в localStorage, страница не индексируется,
  обновление посреди теста однозначно.
- 15 оригинальных вопросов, все шесть тем юнита, таблицы-стимулы и компонент
  `PPF` (инлайновый SVG, цвета из токенов темы).
- Прогресс «вопрос N из 15» с полосой.
- Замер времени и числа возвратов по каждому вопросу — пишется с первого
  запуска, хотя таймер не показывается: иначе на следующей итерации нечем
  будет считать блок про тайминг.
- Экран результатов: счёт, три самые дорогие темы, разбивка по всем шести
  темам, разбивка по навыкам, привязанный к результату CTA, полный разбор
  ответов с разбором дистракторов.
- Незавершённая попытка предлагается к продолжению.
- Карточка преподавателя: строка авторства на входе, полная карточка рядом с
  предложением записаться. Данные — в `src/config/teacher.ts`, всё взято с её
  собственного сайта, ничего не додумано.
- Две формы на экране результатов: запись на бесплатный звонок и отправка
  результатов родителю. Обе уходят письмом через `/api/contact`.
  Валидация на клиенте и на сервере, ловушка для ботов, ограничение частоты.
- Оформленная страница 404 со списком существующих тестов; `/practice-test`
  и `/practice-test/ap-microeconomics` ведут на доступный тест, а не в 404.

## Чего сознательно нет

Таймер и пауза, палитра вопросов, флаги, клавиатурная навигация, полоса
готовности (нужны пороги от преподавателя), сбор email, `/r/[shareId]`, хаб
тестов, `/about`, `/services`, `/legal`, аналитика, деплой.

## Ключевые решения

**Ось роутинга — экзамен, а не предмет.** `TestScope` — размеченное
объединение: `{kind:'unit'}` и `{kind:'full'}`. Полный экзамен станет второй
веткой того же экрана результатов, а не новым экраном: меняются только шапка
и уровень разбивки.

**`priority = (1 − доля верных) × вес темы в тесте`** — наверх выходят не
просто слабые темы, а слабые и весомые, то есть те, что реально стоят баллов.
Единственное место, где считается «что тебе стоит баллов»; покрыто тестами.

**Прогноз балла 1–5 не показывается.** По одному юниту его предсказать нельзя
(Unit 1 — это 12–15% экзамена), и показывать его значило бы врать.

**`Attempt.testSlug`** хранится в попытке: ссылки на результаты вечные, и
результат, полученный сегодня, должен корректно отрисоваться в мае, когда
рядом появятся другие тесты.

**Диаграммы — инлайновый SVG, а не библиотека графиков.** Это не график
данных, а схема: нет рядов, легенды и значений, зато есть именованные кривые,
подписанные оси, точки, стрелки сдвига и заштрихованные области. Recharts,
Chart.js и D3 приспособлены под первое и мешают второму. Общие примитивы
(`оси со стрелками, направляющие, маркеры точек, шкалы`) лежат в
`components/diagrams/primitives.tsx`, чтобы все следующие девять диаграмм
говорили на одном визуальном языке.

**Родитель — отдельный путь, а не приписка.** Тест проходит школьник, платит
родитель. Первый звонок бесплатный, поэтому школьник может записаться без
разрешения; отдельная форма отправляет родителю письмо, понятное взрослому
без контекста. Без этого воронка рвётся ровно в точке оплаты.

**Кому что адресовано.** Сайт преподавателя написан для родителей («You paid
thousands of dollars in your child's education»), а тест проходит школьник.
Поэтому её родительские формулировки живут в письме родителю, а на экране
после теста школьник читает текст, обращённый к нему. Обращение к «your
child» на экране, который смотрит шестнадцатилетний, работает против нас.

**Провайдер писем спрятан за одной функцией** (`lib/email.ts`) и выбирается
по переменным окружения: SMTP, Resend или ничего. Остальной код о нём не
знает. Если провайдера нет, функция возвращает `not_configured`, а форма
показывает запасной путь: форма, которая делает вид, что отправила, хуже,
чем её отсутствие. Выбор провайдера покрыт тестами — это ветвление решает,
уходят письма или нет.

**Анонимный `visitorId` в localStorage** — ничего не стоит сейчас, позже
позволит показать прогресс по всем пройденным юнитам без регистрации.

## Происхождение вопросов

Все вопросы написаны с нуля. Материалы College Board (Test Booklets, банк
AP Classroom) не использовались: их условия запрещают распространение и
передачу в генеративные системы. Из официальных источников взята только
публичная сетка тем CED (1.1–1.6).

Дисклеймер о товарном знаке стоит в футере каждой страницы — это требование
College Board, не украшение.
