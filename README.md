# AP® Econ diagnostic

Диагностические тесты по AP® Microeconomics: Unit 1 и Unit 2. Вертикальный
срез: ученик открывает ссылку, отвечает на вопросы и получает разбор —
счёт, темы, которые стоят ему баллов, и объяснение каждого вопроса.

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
```

Тесты:
`/practice-test/ap-microeconomics/unit-1` · `/practice-test/ap-microeconomics/unit-2`

```bash
npm run typecheck   # tsc --noEmit
npm run test        # подсчёт результатов и выбор почтового провайдера
npm run build
```

## Перед показом ученикам

1. **Способ связи** — `src/config/cta.ts`, поле `mode`:
   - `contact` (сейчас) — без форм: Instagram и подготовленные письма.
     Работает всегда, ничего не требует.
   - `form` — формы записи и отправки родителю через `/api/contact`.
     Включать только когда в окружении есть SMTP или Resend, иначе форма
     будет упираться в запасной путь.
   - `booking` — прямая ссылка на сервис записи.

   Код форм и API никуда не делся: переключение — одна строка.
2. **Фотографии** — обе на месте: `public/olga.jpg` (512×512, круглый аватар,
   кадр по голове и плечам) и `public/olga-portrait.jpg` (600×800, вертикальный
   портрет для главной). Если файл пропадёт, компонент сам покажет монограмму —
   битой картинки не будет ни при каком раскладе.
3. **Отправка писем** — скопировать `.env.example` в `.env.local` и заполнить
   один из двух блоков:
   - **SMTP её ящика** (`SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`) — бесплатно,
     домен не нужен, письма уходят с её реального адреса. Для Gmail нужен
     «пароль приложения», обычный пароль не подойдёт. Это путь на время
     разработки.
   - **Resend** (`RESEND_API_KEY`, `EMAIL_FROM`) — когда появится свой домен:
     Resend без подтверждённого домена отправлять не даёт.

   Если заполнены оба, приоритет у SMTP. Если не заполнен ни один, формы
   работают, но письмо не уходит: пользователю показывается запасная ссылка
   mailto, а письмо печатается в консоль сервера. Молча терять заявки нельзя.

## Что входит в эту итерацию

- Два теста: `/practice-test/ap-microeconomics/unit-1` (15 вопросов, шесть
  тем) и `/practice-test/ap-microeconomics/unit-2` (20 вопросов, девять тем).
  Каждый — три состояния на одном URL: `idle` (лендинг и правила) →
  `running` (движок) → `done` (результаты).
  У движка нет своего URL: состояние в localStorage, страница не индексируется,
  обновление посреди теста однозначно.
- 35 оригинальных вопросов: 15 на Unit 1 и 20 на Unit 2, все темы обоих
  юнитов, таблицы-стимулы и два компонента диаграмм — `PPF` и `SupplyDemand`
  (инлайновый SVG, цвета из токенов темы).
- Прогресс «вопрос N из M» с полосой.
- Замер времени и числа возвратов по каждому вопросу — пишется с первого
  запуска, хотя таймер не показывается: иначе на следующей итерации нечем
  будет считать блок про тайминг.
- Экран результатов: счёт, три самые дорогие темы, разбивка по всем темам
  юнита, разбивка по навыкам, привязанный к результату CTA, полный разбор
  ответов с разбором дистракторов.
- Незавершённая попытка предлагается к продолжению.
- Карточка преподавателя: строка авторства на входе, полная карточка рядом с
  предложением записаться. Данные — в `src/config/teacher.ts`, всё взято с её
  собственного сайта, ничего не додумано.
- Два пути связи на экране результатов: школьнику — Instagram и письмо с
  подставленным результатом, отдельно — отправка результатов родителю.
  Тексты писем общие с формами (`lib/contact-links.ts`), поэтому при
  переключении режима человек получает одно и то же.
- Формы записи и отправки родителю через `/api/contact` — написаны, покрыты
  валидацией на клиенте и сервере, ловушкой для ботов и ограничением частоты,
  но выключены до настройки почты.
- Главная: крупный портрет в паспарту, её заголовок и подводка, список
  тестов, её список результатов, родительский блок и биография — тексты с её
  сайта, приведённые к правилам знака AP®.
- Страница экзамена `/practice-test/ap-microeconomics` со списком юнитов и
  устройством экзамена; `/practice-test` ведёт на неё. Оформленная страница
  404 со списком существующих тестов.

## Чего сознательно нет

Таймер и пауза, палитра вопросов, флаги, клавиатурная навигация, полоса
готовности (нужны пороги от преподавателя), сбор email, `/r/[shareId]`,
выбор экзамена на `/practice-test` (экзамен пока один), `/about`,
`/services`, `/legal`, аналитика, деплой.

## Ключевые решения

**Ось роутинга — экзамен, а не предмет.** `TestScope` — размеченное
объединение: `{kind:'unit'}` и `{kind:'full'}`. Полный экзамен станет второй
веткой того же экрана результатов, а не новым экраном: меняются только шапка
и уровень разбивки.

**В Unit 2 двадцать вопросов, а не пятнадцать.** Тем там девять против
шести, и юнит весит 20–25% экзамена против 12–15%. На пятнадцати вопросах
трети тем досталось бы по одному, а `priority` считается от доли верных: при
одном вопросе доля бывает только 0% или 100%, и треть разбора превратилась бы
в подбрасывание монеты. Двадцать дают минимум по два на каждую тему. Число
вопросов — не косметика, а то, что определяет, работает диагностика или нет.

**Все схемы Unit 2 построены на одном рынке** (`D: p = 80 − q`,
`S: p = 20 + 0,5q`, равновесие 40/40). Ученик разбирается в картинке один раз,
а дальше отвечает на вопрос, а не читает её заново. `SupplyDemand` ничего не
вычисляет сам: точки, ценовые линии и подписи приходят из данных вопроса.
Диаграмма, которая сама «находит» равновесие, рано или поздно найдёт его не
там, где написано в объяснении. Все числа в объяснениях выведены из этих двух
уравнений и проверены счётом.

**Страница экзамена — не редирект.** Пока тест был один,
`/practice-test/ap-microeconomics` перебрасывал на него, и это было честно.
С двумя тестами редирект начал обманывать: человек просил «все тесты по
AP Micro», а получал один, не узнав про второй. Вторая причина важнее:
«AP Microeconomics practice test» ищут в разы чаще, чем «AP Micro Unit 1
practice test», и редирект выбрасывал ровно ту страницу, которая под этот
запрос и нужна. Отсюда же блок про устройство экзамена — он отвечает на
вопрос, с которым сюда приходят из поиска. Цифры формата сверены по
apcentral.collegeboard.org и должны сверяться заново перед каждым учебным
годом.

**Список тестов и раздел с боковым заголовком — общие компоненты**
(`components/TestCard.tsx`, `components/Section.tsx`). Вынесены не ради
экономии строк, а чтобы главная и страница экзамена совпадали по построению,
а не по внимательности: скопированная карточка расходится с оригиналом на
первой же правке.

**Факты о юните живут в определении теста, а не в вёрстке.** Оговорка
«этот тест охватывает только Unit 1» и обещание «разбивка по шести темам»
были вписаны в компоненты словами — на втором тесте оба начали врать.
Теперь первое берётся из `test.unitLabel`, а второе просто не называет число.

**`priority = (1 − доля верных) × вес темы в тесте`** — наверх выходят не
просто слабые темы, а слабые и весомые, то есть те, что реально стоят баллов.
Единственное место, где считается «что тебе стоит баллов»; покрыто тестами.

**Прогноз балла 1–5 не показывается.** По одному юниту его предсказать нельзя
(Unit 1 — это 12–15% экзамена, Unit 2 — 20–25%), и показывать его значило бы
врать.

**`Attempt.testSlug`** хранится в попытке: ссылки на результаты вечные, и
результат, полученный сегодня, должен корректно отрисоваться в мае, когда
рядом появятся другие тесты.

**Диаграммы — инлайновый SVG, а не библиотека графиков.** Это не график
данных, а схема: нет рядов, легенды и значений, зато есть именованные кривые,
подписанные оси, точки, стрелки сдвига и заштрихованные области. Recharts,
Chart.js и D3 приспособлены под первое и мешают второму. Общие примитивы
(`оси со стрелками, направляющие, маркеры точек, шкалы`) лежат в
`components/diagrams/primitives.tsx`, чтобы все следующие диаграммы говорили
на одном визуальном языке. На них уже построены `PPF` и `SupplyDemand`.

**Родитель — отдельный путь, а не приписка.** Тест проходит школьник, платит
родитель. Первый звонок бесплатный, поэтому школьник может записаться без
разрешения; отдельная форма отправляет родителю письмо, понятное взрослому
без контекста. Без этого воронка рвётся ровно в точке оплаты.

**Кому что адресовано.** Сайт преподавателя написан для родителей («You paid
thousands of dollars in your child's education»), а тест проходит школьник.
Поэтому её родительские формулировки живут в письме родителю, а на экране
после теста школьник читает текст, обращённый к нему. Обращение к «your
child» на экране, который смотрит шестнадцатилетний, работает против нас.

**Ширина задаётся ролью, а не на глаз** (`tailwind.config.ts`). Три значения
на весь проект: `measure` (42rem) — строка прозы, около 70 знаков; `reading`
(48rem) — колонка теста и разбора, где важна только читаемость; `content`
(68rem) — страницы с двухколоночной вёрсткой. Раньше везде стоял `max-w-3xl`,
и на широком мониторе сайт выглядел узкой полосой, а заголовок в 48px делил
эти 768px с портретом и рвался на четыре строки.

**Разделы главной — с заголовком в боковой колонке.** От 1024px заголовок
уходит влево, содержимое занимает остальное. Это единственный честный способ
занять ширину: расширять саму колонку прозы нельзя (строка длиннее 70 знаков
читается хуже), а оставлять справа пустоту — то, на что жалуются в первую
очередь. Ниже 1024px колонки схлопываются в обычный порядок. Ширина колонки
(18rem) подобрана по самому длинному заголовку в реальном шрифте: «About Dr.
Olga Shalamai» должен помещаться в одну строку.

**Шрифты лежат в репозитории** (`src/fonts/`, подключение — `next/font/local`
в `app/layout.tsx`), а не скачиваются с Google при сборке. Сборка не должна
зависеть от сети: `next/font/google` тянет файлы в момент build, и в любом
окружении без доступа к fonts.gstatic.com шрифт молча подменяется системным —
то есть вёрстка, проверенная в одной среде, не проверена ни в одной. Файлы —
латинские переменные подмножества Inter и Source Serif 4 из пакетов
`@fontsource-variable/*` (те же шрифты, лицензия SIL OFL); как обновить,
написано в комментарии в `layout.tsx`. Новых зависимостей нет.

**Запасные шрифты живут внутри `var()`, а не в `:root`.** `next/font`
объявляет `--font-sans` и `--font-serif` классом на `<html>`, у которого та
же специфичность, что у `:root`. Пока фолбэки стояли отдельным объявлением в
`globals.css`, они перебивали подключённые шрифты, и сайт всё это время
рисовался системной гарнитурой — разной на разных машинах. Правильная форма —
`var(--font-serif, ui-serif)` в `tailwind.config.ts`: переменной нет —
подставится запасной, и остаток списка сохранится.

**`text-balance` на всех заголовках.** Браузер выравнивает строки заголовка
по длине, вместо того чтобы набивать первую до упора и оставлять на второй
одно слово. Для прозы — `text-pretty`: он убирает висячие строки, но не
трогает длину.

**Портрет — один компонент на три размера** (`components/Portrait.tsx`).
Везде вертикальный кадр 3:4 в паспарту: фон снимка почти совпадает с нашим
тёплым белым, и без оправы фотография растворялась в странице. Круглый аватар
из первой версии убран — из-за него экран результатов говорил о преподавателе
иначе, чем главная. Исключение — строка авторства: на 44 пикселях паспарту
превращается в шум, а вертикальный кадр — в человека посреди комнаты, поэтому
там квадратный кроп `olga.jpg` в тонкой рамке.

**Фавиконка — цифра 5, её же шрифтом.** Это обещание сайта («reach a 5») и
единственная форма, которая читается в 16 пикселей: монограмма «OS» там
слипается, а график тем более. Контур снят с Source Serif 4 (wght 600) и
превращён в путь — SVG-фавиконки не подгружают веб-шрифты, `<text>` там
отрисуется чем попало. Кремовая цифра на чернильном квадрате: тёмная плашка
одинаково видна и на светлой, и на тёмной панели вкладок.

Три файла в `src/app/`, Next подключает их сам по имени: `icon.svg` (основной),
`favicon.ico` 16/32/48 (Safari до 16 и старый Edge SVG-фавиконки не понимают),
`apple-icon.png` 180×180 — без скруглённых углов, потому что iOS накладывает
собственную маску, а прозрачные углы делает чёрными. Перерисовать: изменить
`icon.svg` и пересобрать из него PNG и ICO любым рендерером.

**Знак ® в крупных заголовках набирается надстрочным** (`components/Reg.tsx`)
и привязывается к предыдущему слову неразрывной группой: иначе строка рвётся
между «AP» и «®». В полный кегль знак выглядит громоздко, а убрать его нельзя:
правила College Board требуют символ при каждом упоминании.

**Instagram стоит первым, а не письмо.** Подростку написать в директ проще,
чем составить письмо, и порог входа здесь важнее формальности. Родителю —
наоборот, письмо: взрослые не пишут в директ незнакомым преподавателям.

**Провайдер писем спрятан за одной функцией** (`lib/email.ts`) и выбирается
по переменным окружения: SMTP, Resend или ничего. Остальной код о нём не
знает. Если провайдера нет, функция возвращает `not_configured`, а форма
показывает запасной путь: форма, которая делает вид, что отправила, хуже,
чем её отсутствие. Выбор провайдера покрыт тестами — это ветвление решает,
уходят письма или нет.

**Анонимный `visitorId` в localStorage** — ничего не стоит сейчас, позже
позволит показать прогресс по всем пройденным юнитам без регистрации.

## Происхождение вопросов

Все вопросы написаны с нуля. Материалы College Board (Test Booklets, банк
AP Classroom) не использовались: их условия запрещают распространение и
передачу в генеративные системы. Из официальных источников взята только
публичная сетка тем CED (1.1–1.6).

Дисклеймер о товарном знаке стоит в футере каждой страницы — это требование
College Board, не украшение.
